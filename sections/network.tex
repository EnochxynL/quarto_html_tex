# The (Human+AI)$^{2}$ Research Network {#sec:network}

![研究网络](figures/fig_human_ai_network.png "(Human+AI)$^{2}$ 研究网络。每位研究者通过一个研究智能体与共享的 \ara{} 网络交互，使用 \texttt{/submit}、\texttt{/retrieve} 和 \texttt{/fork} 命令；智能体之间亦可直接协作。"){#fig:network}

前文各节描述了 \ara{}-原生技术栈的组成部分：协议（\S\ref{sec:protocol}）、在开发过程中将工作捕获到构件中的实时研究管理器（\S\ref{sec:live-pm}）、导入既有文献的编译器（\S\ref{sec:ingestor}）以及对其进行验证的 Seal 把关审阅流水线（\S\ref{sec:review-system}）。这些组件组合起来，构成了一个科学交流系统，其主要对象不再是静态文档，而是 \ara{} 本身：一个统一的规范构件，人类在两端指挥智能体对其进行创作、认证、渲染和扩展。我们将由此形成的结构称为 **(Human+AI)$^{2}$ 网络**（图~\ref{fig:network}）。

在生产者一侧，研究者不再以论文为目标；他们追求问题，而作为产出的论文在此过程中自动积累为 \ara{}：实时研究管理器在日常工作中将每项决策、每条死胡同和每个已确认的论断纳入构件，编译器按需导入既有来源，在任何里程碑节点，构件经过 Seal 流水线并公开注册，另一个团队可以复刻（fork）一个通过认证的构件，扩展其论断，保留对父构件的署名，并将差异提交以重新审阅。
在消费者一侧，由于 \ara{} 是规范性的，智能体可按需将其渲染为读者所需的任何界面（论文、视频、幻灯片、交互式演示或基于语境的对话），并根据读者的专业水平、注意力预算和意图进行调整。

由于两端均由智能体中介，且构件是唯一的持久化状态，贡献在构件层面而非句子层面累积：发布成为类似 Git 的操作，审稿人通过他们偏好的界面消费经 Seal 认证的构件，下游智能体将 \ara{} 作为结构化基线、训练环境或新问题的起点来读取。其结果是一个可查询的科学公地，其中每项贡献都是可执行的差异，理解、复现和扩展的成本随着每个新构件的加入而下降，而非与之对抗上升。\S\ref{sec:eval} 探讨当今的智能体是否已能在该基座上运行；\S\ref{sec:discussion} 则勾画了近期、中期和远期的扩展方向。
