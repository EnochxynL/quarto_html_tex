# {{< ara >}} 编译器 {#sec-ingestor}

原生智能体路径（\ref{sec-live-pm}）通过在研究过程中捕获涌现的知识，生成最高保真度的 {{< ara >}}。
然而，科学记录中包含了数以百万计的、从未被结构化的遗留 PDF，而原生智能体路径无法回溯至这些历史文献。
除 PDF 本身之外，研究知识还分散在各种补充性来源中：GitHub 仓库编码了正文中省略的实现决策，专家策划的评估量规编码了领域实践者所认定的核心论断，记录下来的实验轨迹则保存了论文系统性地加以抑制的失败模式。
为了弥合这一鸿沟，我们提出了 **{{< ara >}} 编译器**，这是一项智能体技能，能将任意的遗留研究来源组合转换为一个完整的 {{< ara >}}。^[<https://github.com/AmberLJC/Agent-Native-Research-Artifact>]
质量通过两个阶段来保证。在编译过程中，编译器仅使用 ARA 认证第一级作为环内验证信号。编译完成后，成品构件进入下游认证流水线，由第二至第三级评估其论证性支撑和经验性可复现性（\ref{sec-liveness}）。

## 设计原则 {#sec-ingestor-principles}

#### 通用输入，规范输出。

编译器是多对一的：它接受任意组合的 PDF、代码仓库、数据集、人类策划的量规（例如 PaperBench [@starace2025paperbench] 的论断分解）以及实验轨迹日志（例如 RE-Bench [@wijk2025rebench] 中记录论文所省略之失败的追踪数据），且始终输出一个符合 \ref{sec-protocol} 规范的单一 {{< ara >}}。
降级是优雅的：仅凭一个 PDF 就能生成一个具有桩级物理层的有效构件；更丰富的输入则能逐步填充更完整的层。

#### 高保真保存。

叙事性论文进行压缩和筛选；编译器则进行解压缩和恢复。
来源中的每一个数值结果、超参数、架构细节和负面发现都必须出现在构件的*某处*，任何 PDF 中可获取但 {{< ara >}} 中缺失的信息都构成编译失败（在 \ref{sec-eval-understanding} 中进行评估）。
保存是忠实于来源的；*丰富化*（\ref{sec-collective}）则单独发掘出任何单一来源都无法表达的跨构件模式。

#### 知识谱系，而非扁平提取。

叙事性编译会破坏连接论断与实验、实验与证据、证据与代码的*溯源链*。
纯文本抽取能恢复内容，但无法恢复这些连接：将 PDF 解析为 Markdown 会填充四个目录，却使它们在结构上彼此孤立。
编译器执行*取证重建*，从那些仅隐含存在谱系的来源（散落在正文、图注、附录表格和代码注释中）中恢复跨层取证绑定（\ref{sec-layers}），从而使智能体能够将任意论断向下追溯至代码，或向上追溯至其假设。
编译的核心问题在于恢复这一谱系，而非填充各层。

## 编译器实现 {#sec-ingestion-skill}

针对叙事性 PDF 实现这些原则，需要具体的机制来解决正文如何模糊化结构、谱系和来源多样性的特定方式。
编译器被实现为单一智能体技能（图 \ref{fig-ingestor-pipeline}），引导编码智能体完成从遗留来源到 {{< ara >}} 格式的转换。
技能提示词编码了完整的 {{< ara >}} 模式、字段级需求以及结构化的生成协议。
我们在下文描述关键要素；完整的技能规范复现于附录 \ref{sec-ingestor-prompt}。

#### 自顶向下生成。

该技能指示智能体*自顶向下*地构建构件，如同研究者向新合作者解释其工作的方式：先讲高层概念，再讲细节，最后讲实现。
具体而言，智能体经历四个阶段。
*语义解构*剥离叙事框架，以暴露原始研究内容（公式形式、配置、结果、依赖关系、失败方法），并将其改写为事实密集的电报式形式，从而在来源层面消除叙事税（Storytelling Tax）。
*认知映射*填充 `/logic`：动机链（观察 $\to$ 缺口 $\to$ 洞察）、带有证明指针的可证伪论断、形式化概念以及解决方案结构，且每个论断都关联至验证它的实验。
*物理落地*生成 `/src`：带注释的配置、类型化代码桩以及环境清单；当有代码仓库可用时，桩被替换为实际实现，智能体执行*代码-论文对齐*，将代码库与论断进行交叉比对，以显露出隐性知识——隐含假设、无文档记录的技巧、额外参数 [@li2026tacit]——并将其作为溯源标记的启发式规则写回 `/logic`。
*探索图谱提取*将研究 DAG 重建为嵌套的 YAML 树，其中死胡同叶节点记录了假设、失败模式和教训。
这种顺序确保每一层都受其上一层的指导：认知结构引导物理层生成，而探索图谱为两者提供上下文。

#### 通过验证反馈的迭代精化。

初始生成后，ARA 认证第一级检查（\ref{sec-liveness}）——包括模式一致性、跨层引用解析、必填字段完整性——在同一智能体会话中运行，将失败返回为结构化的诊断信息，驱动针对性修复。
这种生成$\,\to\,$验证$\,\to\,$修复的循环通常在 2--3 轮中收敛，将第一级转变为可操作的反馈，而非事后报告。

#### 来源感知的丰富化。 {#sec-collective}

辅助性来源被路由至其最直接填充的层：代码仓库将 `/src` 中的桩替换为经过验证的实现；评估量规通过专家验证的论断分解来锚定 `/logic`；轨迹日志则用 PDF 所省略的死胡同节点来播种 `/trace`。
当已有先前编译的 {{< ara >}} 库可用时，编译器进一步执行*集体推断*：从同领域构件中检索启发式规则和配置，标记出当前论文遗漏的常见模式，并将其添加为标记为 `collective_inference` 的候选启发式规则，使下游智能体能够区分陈述性知识与推断性知识。
