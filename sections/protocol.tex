# \ara{} 协议 {#sec:protocol}

智能体原生研究构件（\ara{}）协议定义了一套文件系统本体，将计算机科学研究从叙事性文档转变为一个机器可执行的知识包。
我们分别阐述其设计理念（\S\ref{sec:philosophy}）和分层架构（\S\ref{sec:layers}）。
图~\ref{fig:lrm-overview}（\S\ref{sec:live-pm}）展示了实时研究管理器如何在长时间尺度上，在人--AI 研究过程与活态构件之间进行协调。

## 设计理念 {#sec:philosophy}

\ara{} 协议植根于唯一原则：**知识重于叙事**——研究过程中产生的有组织、不断演进的知识是第一位的科学对象；叙事性论文只是其编译视图。

#### 结构化的知识容器。

一个智能体与某个研究项目交互时，会提出四类结构上截然不同的问题：这项工作*为什么*有效（科学推理），它是*如何*实现的（可执行代码），沿途*尝试了什么*（探索轨迹），以及*数据是什么*（原始经验证据）。
一篇叙事性论文迫使智能体从同一种线性散文中提取这四类答案，然而这些知识类型在结构上存在内在冲突：推理需要稳定、可引用的单元，而代码持续迭代；探索历史本质上是分支结构的，而叙事强制线性；证据需要机器精度的数值，而散文会约简和转述。
将它们压缩到单一文档中不仅是次优的，更是*有损的*：一旦扁平化为叙事，原始结构便无法恢复。
\ara{} 通过在智能体原生的文件系统结构中，将每种知识类型物化为其专属的层级（图~\ref{fig:ara-structure}），从而消除这种损耗：这些目录是纯文本、可独立查询的，智能体能够使用标准工具调用进行导航、阅读和操作，而无需解析散文或逆向工程代码仓库。
由于智能体上下文窗口是共享且有限的资源，该结构进一步支持*渐进式披露*：智能体仅加载与当前任务相关的层级和文件，避免不必要的上下文污染。

下面四个层级是对第~\S\ref{sec:intro} 节引入的叙事税和工程税的结构性回应：探索图谱复原了被叙事折叠的分支轨迹；认知层与物理层通过取证链接相互绑定，弥合了概念性描述与可执行规约之间的鸿沟。
在每个层级内部，构件文本最大化每词元的信息密度：去除主观修饰语、模糊限定和叙事连接词，需要判断的陈述携带的是溯源信息而非修辞渲染。

## \ara{} 架构 {#sec:layers}

一个智能体与某个研究构件交互时，有四种基本需求：*理解*贡献、*复现*贡献、*从过程中学习*，以及基于原始证据*验证*论断。
\ara{} 将每种需求物化为一层专用层级（图~\ref{fig:ara-structure}），并以清单文件 `PAPER.md` 为根，其 YAML 前置元数据和层级索引使智能体能在 ${\sim}500$ 词元内判定相关性（附录~\ref{app:schema}）。
此分解的制定参考了基于 PaperBench 评分标准提炼的十类复现关键信息分类体系（附录~\ref{app:taxonomy}）。

#### 认知层（`/logic`）。

智能体*首先*阅读 `/logic` 以理解*做了什么以及为什么*：`problem.md` 定义问题空白和核心洞察，`solution/` 指定架构、算法和收敛关键的启发式规则，`claims.md` 提炼可证伪的断言并配以显式证明指针，`experiments.md` 声明验证计划。
`related_work.md` 用智能体可操作的*类型化依赖*取代被动引用：`imports` 注入先验定义，`bounds` 将约束传播到超参数搜索，`baseline` 条目支持自动回归检测，从而将文献综述转变为机器可执行的依赖图。

#### 物理层（`/src`）。

存放*如何实现*——针对贡献类型校准的可执行代码。
算法性贡献使用*内核模式*：仅包含带有类型化 I/O 签名的核心模块，通常比完整仓库小一到两个数量级，从而编码智能体能够按需重新生成环境原生的样板代码。
系统性贡献（CUDA 内核、分布式训练、系统架构）使用*仓库模式*：保留完整实现，但通过 `index.md` 清单加以标注，将每个源文件映射到其所实现的 \ara{} 组件。
`configs/` 为每个超参数标注理由和搜索范围；`environment.md` 锁定依赖、硬件和随机种子（模式规约、取证绑定及详细理由见附录~\ref{app:src-modes}）。

#### 探索图谱（`/trace`）。

`exploration_tree.yaml` 将完整的研究有向无环图（DAG）存储为嵌套 YAML 树，包含五种类型化节点——`question`、`decision`、`experiment`、`dead_end`、`pivot`——其中嵌套编码父$\to$子边，而 `also_depends_on` 字段捕获收敛点。
该格式充当“研究的 git log”：智能体可直接遍历分支，而叙事性论文所丢弃的死胡同节点，则保留了假设、失败模式和教训（图~\ref{fig:exploration-graph}）。

#### 证据层（`/evidence`）。

支撑每个论断的原始输出：`results/` 包含机器可读的指标表和生成数据，附有精确取值和来源注释；`logs/` 捕获训练曲线、资源使用和诊断信息。
它*仅*持有输出，从而每个论断的证明链沿 `claims.md`~$\to$~`experiments.md`~$\to$~`/evidence/` 流动。

#### 隐去真实值实现层级化访问控制。

实验*逻辑*（验证什么）位于 `/logic`；实验*数据*（确切结果）仅位于 `/evidence`。
可以在隐去证据层的情况下向验证智能体授予代码内核和算法描述，从而防止其通过复制预期值来伪造结果。
这种分离还使每个 \ara{} 成为一个即开即用的训练环境：任务位于 `/logic/experiments.md`，奖励位于 `/evidence/`，而偏好信号则蕴含于 `/trace/` 中记录的每一次接受、拒绝和修订之中。

我们认为，当一个*能力足够*的编码智能体能够纯粹基于 \ara{} *零样本*地复现核心论断时——无需人工干预，也不依赖构件本身之外的任何外部上下文——则该 \ara{} 是充分的。因此，充分性是一个相对于能力的准则：它衡量的是构件是否*包含*复现其论断所需的信息，而非当下的任何智能体是否能够充分利用它。在智能体能力的极限处，一个完整的 \ara{} 按定义即是可复现的，因此今天撰写的构件在智能体进化后仍然有效。
