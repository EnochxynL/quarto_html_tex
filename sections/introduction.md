# 引言 {#sec-intro}

研究产生的是一个丰富、分支的知识对象：历经数月的假设检验与推翻，通过反复试错发现的实现技巧，在多个设计方案之间反复权衡，以及解释为何最终选择该方法的完整探索轨迹。
出版将这一对象编译为线性叙事 [@medawar1963fraud; @canini2026stopwriting]，丢弃了失败的实验、隐性的工程知识以及分支探索过程，以迎合人类可读叙事的惯例 [@rosenthal1979filedrawer; @franco2014publication]。
当论文的每一位消费者都是人类时，这种编译代价——源于文档化惯例而非特定文件格式的产物——尚可接受。
但当 AI 智能体需要例行阅读论文以理解领域、复现实验以验证发现、并将已发表方法扩展至新场景时 [@lu2024aiscientist; @liu2026ainative]，这种代价便不可接受：每一项任务恰恰需要被编译所丢弃的知识（图 \ref{fig-overview}）。
更具体而言，这一编译过程带来了两类结构性代价。

![出版将丰富的研究对象编译为有损的叙事（左）；Ara 则将原始对象保存为高保真、智能体可执行的知识包（右）。](figures/fig_legacy_vs_ara_v6.png){#fig-overview}

其一是**叙事税**：将研究过程编译为叙事时，对研究过程知识造成的系统性抹除（图 \ref{fig-storytelling-tax}）。
研究并非线性推进——它在收敛到可发表结果之前，不断分支、回溯，并积累来之不易的失败知识 [@kuhn1962structure; @medawar1963fraud]。
叙事编译将这一过程压扁为一条经过打磨的线性故事，丢弃了每一个失败的实验、被推翻的假设和被放弃的方向。
这种对成功的强调使失败无人记录；尽管现代平台能归档最终制品，但分支式的研究过程仍未被记录，导致不同研究团队独立重复发现同样的死胡同 [@rosenthal1979filedrawer; @franco2014publication]。
我们基于 METR 的 eval-analysis-public 数据集 [@wijk2025rebench] 进行的分析——涵盖 21 个前沿模型在 RE-Bench 上的 24,008 次智能体运行——量化了这一代价（附录 \ref{sec-exploration-tax} 中给出了逐任务分解）：失败运行占总美元成本的 **90.2\%**（占总 token 量的 59.2\%），失败与成功运行的中位 token 比高达 **113$\times$**，无法获取先前失败记录的智能体必须独立重新发现每一个死胡同。
同样被丢弃的还有人类*判断*在整个轨迹中的记录：每一次拒绝、修改和认可，都是关于何谓好的研究的偏好信号——一旦智能体承担了繁重的执行工作，这种信号便成为稀缺资源。叙事编译丢弃了这些信号；而保留的轨迹则将其呈现为结构化的监督信号，可跨项目累积复用。

其二是**工程税**：*足以满足评审者*的文档与*足以满足智能体*的文档之间的鸿沟（图 \ref{fig-info-gap}）。
论文以说服人类评审者所需的细节层级来传达其贡献；代码仓库提供了实现，但未提供执行所需的操作规范。
两者之间是隐性知识 [@polanyi1966tacit]——算法技巧、实现决策和配置选择——这些知识不存在于任何书面文档中，仅能通过直接与实验室接触或费力的逆向工程来传递。
我们通过将 PaperBench 中覆盖 23 篇 ICML 2024 论文的 8,921 条专家标注复现需求 [@starace2025paperbench] 与其源 PDF 逐条对照分类来量化这一鸿沟（附录 \ref{sec-gap-types} 中给出了逐类别分解和鸿沟类型分类法）：尽管已有广泛的制品共享，但仅有 **45.4\%** 的需求被完整规定。
代码开发是最欠规定的类别（充分率为 37.3\%），而仅缺失超参数一项就占所有鸿沟的 26.2\%（完整分解见附录 \ref{sec-gap-types}）：这揭示了论文写作精度（足以产生信念）与智能体操作精度（足以产生正确执行）之间的根本性错配 [@stodden2016enhancing; @baker2016reproducibility]。

两类税负贯穿整个研究史一直存在，因为人类读者始终是那个带宽受限的层，负责处理庞大、非线性的研究轨迹。
如今，强大的 AI 智能体提供了一种更高效的、贴近人类的代理，能够以机器带宽代表读者处理研究轨迹，而三种趋势预示了这样的制品应当具备何种形态。
**第一**，AI 智能体已成为不可或缺的研究伙伴，与人类共同编写代码、运行实验、迭代假设 [@lu2024aiscientist]，LLM 的采用与各科学领域论文产出增长 23.7\%--89.3\% 相关 [@kusumegi2025scientific]；完整的研究轨迹（每一次失败、每一个实现技巧、每一项配置选择、每一次设计转向）如今被捕获为研究者与智能体会话中的机器可读文本，但尚无协议将其作为一等输出来保存。
**第二**，人类与 AI 智能体的信息需求存在分歧：人类略读摘要和图表 [@renear2009strategic]，而智能体受益于详尽信息，因为这些信息严格改善复现、验证和扩展，因此单个人类叙事优化的制品已无法同时服务二者。
**第三**，研究正扩展为大规模并行事业，智能体以机器速度分叉、扩展和合并彼此的工作，瓶颈从个体生产力转向制品的*可操作性*：为顺序人类阅读而编译的叙事型 PDF，无法被分叉、差异比较或合并，但结构化的、无损的制品可以，从而使研究能够如软件般复合增长。

![叙事税：研究以包含死胡同的分支树形式推进（左），但出版将其编译为线性叙事（右），丢弃了所有失败知识。](figures/fig_exploration_tax.png){#fig-storytelling-tax}

现有工作只解决了该问题的部分侧面。
FAIR 原则 [@wilkinson2016fair] 要求数据可发现、可访问，但对研究*论证*的结构未作规定。
RO-Crate [@soilandreyes2022rocrate] 将研究制品打包为档案束，而非可执行对象。
Nanopublications [@groth2010nanopub] 将原子性论断形式化，但缺少复现所需的执行层。
新兴的 `AGENTS.md` 标准 [@openai2025agentsmd] 为代码仓库提供了面向智能体的文档，但并未涉及研究本身的认知结构。
上述工作均未将科学逻辑、可执行代码和探索历史联合结构化为单一可操作对象（\ref{sec-related}）。

我们提出**智能体原生研究构件（{{< ara >}}）**，一种将主要研究对象从叙事文档重塑为智能体可执行知识包的协议，论文则作为底层制品的编译视图（图 \ref{fig-overview}）。
{{< ara >}} 将研究组织为四个相互耦合的层次：*结构化科学逻辑*，将论文的概念抽象提炼为可查询的论断及其依赖图谱；*可执行代码*，附带完整的操作规范；*探索图谱*，保留叙事编译所丢弃的分支研究过程——失败的实验、被推翻的假设和设计转向；以及*有据的证据*，将每一条论断与其原始实证输出相绑定。
在 {{< ara >}} 制品上操作的智能体无需解析散文、逆向工程代码仓库和重新发现死胡同，即可直接查询结构化论断、执行声明式规范、并基于完整决策历史进行后续构建——这是一种设计目标不是被*阅读*、而是被*操作*的研究对象。

为构建围绕 {{< ara >}} 的生态系统，我们开发了三种支撑机制。
**实时研究管理器**（\ref{sec-live-pm}）将研究决策和死胡同作为日常开发的自然副产品加以捕获，在不增加额外文档负担的前提下产出符合规范的制品。
**{{< ara >}} 编译器**（\ref{sec-ingestor}）将遗留 PDF、代码仓库和补充材料翻译为 {{< ara >}} 格式，提供与现有出版生态的向后兼容。
**{{< ara >}} 原生评审系统**（\ref{sec-review-system}）自动化结构验证和预算感知的复现（类似于散文的语法检查器），将专家注意力从机械核对重定向至判断——显著性、新颖性和品味 [@aczel2021billiondollar]。

#### 贡献。

- 我们识别了将研究编译为叙事的两类结构性代价——**叙事税**和**工程税**——并引入**智能体原生研究构件（{{< ara >}}）**：一种将主要研究对象从叙事文档重塑为智能体可执行知识包，并组织为四个相互耦合层次的协议（\ref{sec-protocol}）。
- 我们开发了三种支撑机制：**实时研究管理器**（\ref{sec-live-pm}），在日常开发中捕获研究决策；**{{< ara >}} 编译器**（\ref{sec-ingestor}），将遗留 PDF 和代码仓库翻译为 {{< ara >}} 格式；以及 **{{< ara >}} 原生评审系统**（\ref{sec-review-system}），自动执行客观验证（类似于散文的语法检查器），使人类评审者得以聚焦于判断。
- 我们在三个研究效用层次上评估 {{< ara >}}（\ref{sec-eval}）：*理解*（智能体从制品中可提取到什么）、*复现*（智能体能否重新执行论文的实验）、以及*扩展*（智能体能否在已有结果基础上进一步构建并发现真正新的发现——研究的根本目标）。在所有三个层次上，基于 {{< ara >}} 操作的智能体始终优于阅读论文 PDF 及其关联代码仓库的智能体。
